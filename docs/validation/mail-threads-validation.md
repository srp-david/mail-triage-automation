2026-09-18 사용자 요청: 목록에서 같은 대화를 묶고 펼쳐 개별 메일 선택.

## 동작과 범위

- 기본은 스레드 보기, 선택 상자로 개별 보기로 전환한다. 페이지당 최대 30개 대화이며 메일 수와 대화 수를 구분한다.
- 펼친 대화는 최신 메일부터 표시한다. 대화 정렬도 최신 표시 메일 기준이며 검색 시 검색에 맞는 메일만 포함한다.
- Message-ID는 대소문자를 유지한다. In-Reply-To/References에 나타나는 공통 조상은 원본이 없어도 연결한다. 제목만 같은 메일은 묶지 않는다.
- 개별 메일의 선택 강조, 분석 이력, 처리 상태, 모바일 목록 복귀를 유지한다. 분석/보고서/관련 메일 데이터는 대화 단위로 병합하지 않는다.
- 기존 `/api/mails` 호출은 개별 메일 응답을 유지한다. `view=threads` 요청만 대화 페이지를 반환한다. 검색 결과의 모든 MCP 페이지를 읽고 묶으므로 큰 메일함은 개별 보기보다 조회 비용이 크다.
- 필터 없는 전체 메일함과 검색 조건 내에서만 연결한다. 검색에 제외된 중간 메일에만 연결 근거가 있으면 검색 결과의 그룹이 나뉠 수 있다. 분석 상태 필터는 검색 결과의 연결 그래프를 유지한 채 개별 메일에 적용한다.
- 구버전 MCP가 답장 헤더를 제공하지 않으면 업데이트 안내를 표시한다. 개별 보기로 계속 조회할 수 있다.

## MCP 변경

`C:/Users/david/IdeaProjects/mail-mcp`에서 목록·상세 응답에 `messageId`(목록), `inReplyTo`, `references`를 제공한다.

- `email_thread_headers`는 기존 메일에서 파생한 보조 테이블이다. 기존 메일 ID, UIDL, 원본, 본문, 기존 검색 스키마 버전은 유지한다.
