# 제한 팀 배포와 파일럿

현재 단계는 M1 공용 기반 확인 후 M2의 실제 팀 수용 준비다. [현재 상태](../current-status.md)의 hosted 합성 검증은 실제 두 PC 업무 파일럿을 대신하지 않는다. 최종 완료 기준은 [통합 계획](../implementation-plan.md)의 M1~M3를 따른다.

## 1. 배포 단위

| 공통으로 전달 | 각 PC에서 준비 | 전달하지 않는 것 |
|---|---|---|
| 검토한 ZIP·checksum·서버 주소/issuer/audience·사용 안내 | 앱 사용자 계정, 개인 MCP·AI 로그인과 경로, 허용된 ERP 읽기 자료 | DB 비밀번호·서명키·관리용 API 키·다른 사용자의 secrets/work |

팀원에게 Supabase 계정이나 DB 계정을 만들 필요는 없다. 앱 관리자가 사용자명 계정을 발급하고 임시 비밀번호는 보호된 전달 경로로 보낸다. 첫 로그인 후 변경한다. 임시 비밀번호·실메일·고객 화면을 일반 피드백 문서나 Git에 붙이지 않는다.

현재는 수동 후보 설치를 지원해야 한다. [Windows 안내](windows.md)의 실행·종료 절차를 담당자가 먼저 확인한다. 간편 설치 묶음과 배포 신뢰 경로는 아직 남은 작업이며 배포 파일을 이미 게시했다고 표현하지 않는다.

## 2. 순서

1. 2명/2PC, 담당자·지원 창구·지정 업무 사례를 정한다. 원본/코드의 AI 전송과 공용 보고서 저장 범위를 확인한다.
2. 후보 설치·정상 시작/종료·첫 로그인·비밀번호 변경을 확인한다.
3. PC별 Mail MCP·개인 Agent·읽기 자료를 연결한다. 실제 ERP DB provider는 별도 구성이므로 자동 연결로 간주하지 않는다.
4. 본인 source·Runner 등록, Agent 선택, 명시적 loop 시작을 수행한다.
5. 지정 사례의 분석·추가 질문·보고서 저장·처리 상태·공유를 확인한다.
6. 권한·원본 부재·중단/재전송·업데이트를 검사하고 제한적으로 업무 피드백을 받는다.
7. 남은 운영 항목과 결함을 확인해 확대 여부를 결정한다. 백업 보류를 완료로 바꾸지 않는다.

## 3. 수용 기록

| 사례 | 기대 결과 |
|---|---|
| 계정 | 임시 로그인은 첫 변경만 허용, 변경 후 정상 사용, 비활성 계정 거절 |
| 격리·공유 | 같은 숫자 메일 ID라도 source가 다르면 분리, 공유 전 거절·명시 공유 후 허용 |
| 원본 부재 | 다른 PC의 공유 보고서는 조회, 없는 MCP 원문은 제한 안내 |
| 분석 | 개인 Agent로 지정 근거를 읽고 결과 저장, 추가 답변은 새 실행으로 기록 |
| 개발자 PC 종료 | 공용 API와 다른 팀원 PC는 사용 가능. 꺼진 PC의 Runner가 계속 도는 것으로 기대하지 않음 |
| Runner 중단 | 작업 식별·receipt 보존, lease 만료/복구 확인, 임의 중복 분석 없음 |
| 응답 유실 | 같은 ID·결과 재전송, 다른 계정이나 오래된 lease의 제출 거절 |
| 권한 회수 | 다음 조회·heartbeat·결과 제출에서 현재 권한 반영 |
| 동기화 | batch 결과·중지·불확실 상태 구분, 무조건 재실행 없음 |
| 설치·업데이트 | 한글 경로·포트 충돌·중단·직전 버전 복귀·개인 상태 보존 |
| 앱 내 업데이트 도입 후 | 인증/사용자별 버전·stable/test·API 호환, 분석/동기화 종료 대기, 다운로드/서명 실패, 설치·재시작/롤백, outbox 보존 |
| 백업/복원 | 현재 보류. 실제 운영 완료에는 별도 외부 백업·격리 복원 근거 필요 |

기록은 날짜, 버전, PC/사용자 별칭, 합성/실 Agent/실업무 구분, 작업 ID, 기대/실제 결과, 안전한 오류 코드·결함 번호를 포함한다. 코드 검사·실행 성공·고객 업무 해결은 별도로 판정한다. 초기 실제 업무 5일 관찰은 계획 제안이며 확정 일정이 아니다.

## 4. 이전 파일럿 검사기의 경계

[과거 JSON 양식](../archive/pilot-record.example.json)과 `scripts/check-pilot-record.mjs`에는 Auth0 시절의 `verifiedEmail` 및 두 Agent 필수 검사가 남아 있다. 현재 사용자명 파일럿의 자동 승인 도구로 사용하지 않는다. 새 양식/검사기 정합화는 향후 배포 묶음 작업에서 다루며, 이번 문서 정리로 제품 스크립트를 변경하지 않았다.

현재는 위 표의 실제 증거로 수동 검토한다. 미수행을 passed로 채우거나 백업이 보류된 기록으로 전체 수용 완료를 선언하지 않는다. 검사기 정합화는 계획 T1이며 이번 문서 갱신에서는 스크립트를 수정하지 않았다.

## 5. 신규 기능의 수용 구분

초기 후보 설치는 수동 경로로 진행할 수 있다. [Release 업데이트](releases.md)의 실제 제공/버튼 설치는 U1~U3 구현 후 별도 수용하고, 수동 설치 성공으로 대체하지 않는다. public 저장소의 파일은 누구나 받을 수 있으므로 API의 사용자별 안내를 파일 접근 제한으로 안내하지 않는다. 저장소/공개 범위·게시/서명·지원 채널 정책은 D13을 따른다.

보고서 대화·보고서 반영/버전·낙관적 락은 계획 C1~C3의 M3 확장 배치안이다. 출시 범위가 정해지면 두 사용자 동시 저장·초안 보존·권한 회수·다른 PC 대화 복원을 수용표에 추가한다. 현재 추가 답변→재분석과 구분하며 첫 파일럿에 미구현 기능을 필수로 요구하지 않는다. 구현 작업 시작·PR은 M5 수용이다.
