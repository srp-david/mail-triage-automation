# 로그인 유지와 자동 로그인

확인 기준: 2026-09-28 현재 저장소의 사용자명 인증·Windows 설치 앱 코드. 실제 개인 세션의 남은 시간이나 운영 서버의 배포 코드 일치를 이번 문서 작업에서 조회하지 않았다.

## 처음 로그인하기

공용 서버 주소가 설정된 앱에서 관리자가 발급한 사용자명과 임시 비밀번호로 로그인한다. 최초 로그인에서는 비밀번호를 변경하고 새 비밀번호로 다시 로그인한다. 신규 PC에는 해당 PC에서 로그인이 필요하며, Mail MCP·AI 도구 연결도 PC별로 설정한다.

관리자 메뉴는 사용자명이 아니라 `admin` 권한에 따라 표시한다. 특정 이름의 계정만을 위한 메뉴가 아니며 서버에서도 현재 권한을 검사한다.

## 자동 로그인의 흐름

1. 서버가 사용자명·비밀번호를 확인하고 접근 토큰과 갱신 토큰을 발급한다.
2. 설치 앱이 토큰과 만료 시각을 Windows 보호 저장소에 저장한다. 비밀번호 자체는 자동 로그인용으로 저장하지 않는다.
3. 다음 실행에서 앱이 저장된 세션을 읽고 인증 서버·대상 API 정보가 현재 설정과 일치하는지 확인한다.
4. 접근 토큰이 유효하면 사용하고, 인증 요청을 처리할 때 남은 시간이 1분 이하이면 갱신한다.
5. 서버에서 세션·계정 상태를 확인할 수 있으면 로그인 화면을 거치지 않고 접속한다.

현재는 별도의 자동 로그인 선택란 없이 로그인 성공 시 기본적으로 세션을 저장한다. 로그인 유지와 분석·동기화 실행은 별도로 관리하며, 앱을 다시 켠 것만으로 분석을 자동 시작하지 않는다.

## 유효기간과 갱신

| 구분 | 현재 코드의 값 | 의미 |
|---|---|---|
| 접근 토큰 | 5분 | 공용 API 요청 인증 |
| 일반 로그인 세션 | 로그인 시점부터 최대 30일 | 자동 로그인 가능한 전체 기간 |
| 최초 비밀번호 변경용 세션 | 10분 | 임시 비밀번호 로그인 후 변경 진행 |
| 로컬 브라우저 세션 | 발급/재발급부터 8시간 | 브라우저와 내 PC 앱 사이의 인증 |
| 브라우저 진입 ticket | 60초, 한 번 사용 | 바로가기·트레이에서 웹 화면을 여는 진입 자격 |

갱신할 때 접근 토큰과 갱신 토큰을 새로 발급하며, 기존 갱신 토큰은 다시 사용하지 않는다. 갱신은 일반 로그인 세션의 30일 만료 시각을 연장하지 않는다. 따라서 계속 사용해도 30일 이후에는 재로그인이 필요하다.

로컬 브라우저의 8시간도 요청할 때마다 연장되는 유휴 제한이 아니다. 로그인·브라우저 진입 등 쿠키 재발급 시 새 만료 시각을 설정한다. 로컬 쿠키가 만료되거나 앱을 재시작한 뒤에는 바탕화면 바로가기 또는 트레이의 **화면 열기**로 다시 진입한다. 서버 로그인 세션이 유효하면 비밀번호 입력 없이 접속할 수 있다.

## 저장 위치와 보호

기본 설치 위치의 세션 파일은 `%LOCALAPPDATA%\MailTriagePilot\secrets\session.dpapi`다. 설치 위치를 바꿨다면 해당 설치 루트의 `secrets/session.dpapi`를 사용한다.

접근·갱신 토큰을 Windows DPAPI의 현재 사용자 범위로 암호화하고 저장 폴더의 접근 권한을 제한한다. 앱 계정과 Windows 계정은 별개이며, 현재 Windows 사용자 환경 안에 앱의 로그인 세션을 보관한다. 토큰을 브라우저의 localStorage에 저장하지 않는다. 다른 PC나 Windows 계정으로 파일을 복사해 로그인 이전을 처리하지 않는다. 같은 Windows 사용자 권한의 프로세스까지 격리하는 장치는 아니므로 [보안 경계](../security.md)도 참고한다.

## 종료·재부팅·업데이트와 로그아웃

| 행동 | 저장된 로그인 정보와 다음 접속 |
|---|---|
| 브라우저 닫기 | 앱과 저장된 세션 유지 |
| 트레이에서 앱 종료 | 앱은 종료하고 저장된 세션 유지 |
| PC 재부팅 후 앱 실행 | 저장된 세션으로 자동 로그인 시도 |
| 같은 설치 위치에 업데이트 | 보존된 세션으로 자동 로그인 시도 |
| 다른 PC에 새 설치 | 해당 PC에서 계정·비밀번호 입력 필요 |
| 로그아웃 | 로컬 저장 상태를 로그아웃으로 바꾸고 서버에도 해당 세션 폐기 요청 |

자동 로그인 시도는 서버가 해당 세션을 계속 허용하는 경우에 성공한다. 로그아웃 시 서버 폐기 요청이 통신 오류로 실패해도 로컬 로그인 정보는 먼저 해제한다.

## 다시 로그인이 필요한 경우

- 직접 로그아웃하거나 일반 로그인 세션의 30일이 지난 경우.
- 본인이 비밀번호를 변경하거나 관리자가 비밀번호를 초기화한 경우. 해당 계정의 기존 서버 세션을 모두 폐기한다.
- 관리자가 계정 정보를 저장한 경우. 현재는 역할·사용 상태뿐 아니라 **표시 이름만 변경해도 해당 계정의 기존 세션을 모두 폐기**한다.
- 계정 또는 팀 접근이 비활성화되거나 서버에서 세션이 폐기된 경우.
- 저장된 세션이 없거나 읽을 수 없고, 서버 주소·인증 설정이 저장 당시와 맞지 않는 경우. 저장소를 읽지 못하면 로그인 화면 대신 저장소 오류가 표시될 수도 있다.
- 갱신 도중 통신 오류·응답 유실·저장 실패·앱 중단이 발생한 경우. 갱신 전 저장 상태를 `renewing`으로 바꾸고 이전 토큰을 재전송하지 않으므로 재로그인이 필요할 수 있다. 모든 일시적인 통신 오류가 즉시 세션을 삭제한다는 뜻은 아니다.

본인 비밀번호는 **내 계정 → 비밀번호 변경**에서 변경한다. 관리자 초기화는 **관리자 → 계정 관리**에서 수행한다. 비밀번호 변경 후에는 새 비밀번호로 다시 로그인한다.
