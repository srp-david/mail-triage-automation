# 과거 이력 연결 검증 — 2026-09-17

기존 보존 문서 33건 중 보고서 30건을 현재 메일에 연결했다. 메일 목록에서 `이전 이력 1건`이 표시되고, `이 메일 분석 이력` 팝업의 `연결된 이전 이력`에서 Markdown 보고서를 열 수 있다.

## 연결 기준과 결과

- 보고서 및 기존 로그의 Message-ID, 발신자, 제목, 수신시각, 현재 메일 원문을 함께 대조했다. 제목이나 Message-ID만으로 연결하지 않았다.
- 과거 Message-ID가 없는 1건은 보고서가 명시한 원본 덤프의 EntryID, 발신자, 제목, 수신시각과 본문 2문장을 대조하고 현재 MCP ID·Message-ID를 확인했다.
- 수신시각과 발송시각은 별도 항목으로 다뤘다. 연결 대상에서 확인한 차이는 -1~22초이며, 시각 차이만으로 동일성을 판단하지 않았다.
- 누적 보고서 6건은 문서 첫 메일 요약에 명시된 최초 분석 대상에 연결했다. 후속 내용과 당시 상태 기록은 그대로 보존했다.
- 동일 Message-ID가 서로 다른 MCP ID에 존재하는 보고서 1건은 선택 근거가 부족하여 보류했다. 코드 점검 보고서 1건과 여러 메일이 포함된 전체 로그 1건은 독립 문서로 보존했다.

## 실제 검증

- 연결 전 대상 30건의 현재 메일 식별자·본문 해시·보고서 해시를 다시 확인한 뒤 기존 증명 연결 API를 순차 실행했다.
- 연결 후 30건 모두 저장소+메일 ID로 조회되는 보고서와 메일 목록의 이전 이력 건수를 확인했다.
- 원본 파일 33건, 공용 저장 사본 33건의 내용 해시가 연결 전후 동일했다.
- 기존 분석 4건의 실행 ID·상태·결과·보고서 해시·처리 완료 상태가 동일했고, 대상 메일의 분석 횟수와 처리 완료 상태도 유지됐다.
- 실행 중인 웹 앱에서 대표 2건의 목록 배지 → 메일별 이력 팝업 → Markdown 보고서 표시를 확인했다. 이전 이력 메뉴는 연결 30건·미연결 3건, 총 33건을 표시했다. 브라우저 스크립트 오류와 업무 변경 요청은 없었다.
- 실제 분석 재실행, 메일 동기화, 원본 보고서 수정, ERP 코드·DB 수정은 수행하지 않았다.
