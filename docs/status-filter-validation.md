# 메일 검색 상태 필터 — 2026-09-17

메일함 검색 조건에 분석 상태 선택을 추가했다. 기본값은 전체 상태이며, 선택 후 검색 버튼을 누르면 기존 제목/본문·발신자·시작일 조건과 함께 적용된다. 조건을 다시 검색하면 첫 페이지로 돌아간다.

- 분석 대기·분석 중·확인 필요·분석 완료·분석 실패: 최근 분석 실행 상태 기준. 예전 완료 이력이 있어도 최근 재분석이 실패했다면 실패 검색에 포함된다.
- 미분석: 공용 분석 실행과 연결된 이전 이력이 모두 없는 메일. 단순 메일 식별 등록만으로는 분석된 것으로 간주하지 않는다.
- 처리 완료: 사용자가 표시한 업무 처리 상태이며 분석 결과 상태와 독립적이다.
- 이전 이력 있음: 해당 메일에 연결된 과거 문서가 있는 경우다.

`GET /api/mails`의 선택적 `analysis_status` 값을 검증한다. 상태가 전체이면 기존 MCP 검색을 그대로 사용한다. 상태를 지정하면 기존 조건의 검색 결과를 100개씩 읽어 현재 저장소의 분석 이력과 대조한 뒤 필터 결과 건수와 페이지를 계산한다. 현재 페이지에서만 거르는 방식이 아니므로 다음 페이지의 대상도 검색된다. 상위 검색 오류나 진행되지 않는 페이지를 부분 성공으로 표시하지 않는다.

## 검증

- TypeScript 및 viewer 타입 검사 통과.
- 검색 로직 3개 테스트: 최근 상태·처리 완료·이전 이력 구분, 205건 다중 페이지 검색/총건수/마지막 페이지/빈 결과, 기본 검색 유지와 상위 조회 실패 처리.
- PostgreSQL 임시 스키마 API 통합 1개 테스트: 과거 완료 후 최근 실패, 다른 저장소의 동일 숫자 ID, 처리 완료, 이전 문서, 미분석, 잘못된 상태 값 거부. 합성 데이터만 사용하고 임시 스키마 정리.
- 합성 브라우저: 9개 선택값, 복합 조건 전달, 페이지 초기화, 빈 결과, 모바일 가로 넘침 검사 통과.
- 실행 중인 API에 반영 후 실제 완료·실패·확인 필요·이전 이력·미분석·처리 완료 검색을 읽기 전용 검증. 목록의 상태가 공용 이력과 일치했고 이전 이력 30건은 실제 브라우저에서도 확인했다.

실제 분석 실행·메일 동기화·처리 완료 변경은 하지 않았다. API만 교체하고 DB와 Worker는 유지했다. 실제 검색·화면 증거는 Git 제외 디렉터리 `.runtime/status-filter/`에 보관했다.

현재 약 1,100건 메일 환경에서 상태 지정 검색은 약 1.6~2초였다. 정확한 총건수를 위해 전체 후보를 읽으므로 데이터가 크게 늘면 공용 메일 검색 인덱스를 검토한다. 실행 상태가 바뀐 후에는 다시 검색하여 조건에 해당하는 목록을 갱신할 수 있다.
