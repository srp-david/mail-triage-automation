# 팀 배포 계획 통합 안내

2026-09-21 최신 계획은 [통합 구현 계획 v3.1](../implementation-plan.md)에서 관리한다. 이 문서는 안내만 제공한다.

순서는 **공용 API·DB와 로컬 MCP/AI 통합(M1) → 제한 팀 배포(M2) → 피드백·안정화(M3) → 원격 분석(M4) → SR 구현·검증·PR(M5)**다. 최종 자동화를 최초 팀 배포의 선행 조건으로 두지 않는다.

첫 공용 API·DB는 Supabase Edge·PostgreSQL로 배포한다. PoC의 사용자명 인증/관리자/Runner를 원본에 통합하고 [배포 안내](../operations/supabase.md)에 따라 검증한다. AWS 이전과 `srp-rds-maria/cvslog` 재사용은 M3 안정화 이후 검토한다. 로그인은 관리자 생성 사용자명 계정이며 회사 이메일 자동 가입/Auth0는 폐기된 안이다.

- 4절: Supabase 최초 구성, 이후 AWS/DB 이전과 실제 확인 경계
- 5~6절: 인증/PoC 통합·설치/복원·팀 파일럿·피드백/안정화
- 7~9절: 안정화 이후 원격 분석과 SR→PR 계약/검증
- 10~11절: 필요한 결정 시점과 두 리뷰의 반영 결과

기존 계획은 [v2.1 보존본](implementation-plan-history-2026-09-21-v2.1.md)에, 실제 검증은 [검증 기록](../validation.md)에 남긴다. 문서 변경은 AWS 리소스 생성·DB 이관·배포 완료를 뜻하지 않는다.
